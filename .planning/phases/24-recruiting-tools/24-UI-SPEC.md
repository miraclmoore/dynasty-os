## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`), inline badge padding (`px-2 py-1`) |
| sm | 8px | Compact row gaps (`gap-2`), filter bar inter-element spacing |
| md | 16px | Form field gaps (`gap-4`), section padding (`p-4`) |
| lg | 24px | Card body padding (`p-5` ~20px, accept), section-to-section gaps (`gap-6`) |
| xl | 32px | Between major page sections (`gap-8`) |
| 2xl | 48px | Page-level top padding, empty state vertical centering (`py-16`) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Recruit list rows use `py-3 px-4` (12px/16px) — matches existing RosterPage row rhythm; do not change.
- The Hard Sell banner uses `p-4` (16px) — matches existing ScreenshotIngestionPage banner exactly (source: line 1147).
- Toggle controls use `py-2 px-3` (8px/12px) — rounded up from non-conforming `py-1.5` to nearest multiple of 4.
- Inline badge (Hard Sell compact row badge) uses `px-2 py-1` (8px/4px) — rounded up from non-conforming `py-0.5` to nearest multiple of 4.

Source: measured from `RecruitingPage.tsx`, `RosterPage.tsx`, `ScreenshotIngestionPage.tsx` existing elements.

## Typography

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|---------|
| Body / form labels | 14px (text-sm) | 400 (normal) | 1.5 | `text-sm` |
| UI labels / muted | 12px (text-xs) | 400 (normal) | 1.4 | `text-xs` |
| Section headings | 16px (text-base) | 600 (semibold) | 1.2 | `text-base font-semibold` |
| Page headings | 20px (text-xl) | 600 (semibold) | 1.2 | `text-xl font-semibold tracking-tight` |

**Allowed weights: 400 (font-normal) and 600 (font-semibold) only.** `font-medium` (500) and `font-bold` (700) are not used in live UI for this phase.

Font family: `font-sans` (Inter) for all UI text in this phase. Display font (Bebas Neue / Oswald) is not used in this phase — reserved for marketing/card export surfaces only.

**Signing Day Class Card export exception (export surface only — does not apply to live UI):** The PNG card uses `font-display` (Bebas Neue) for the large commit count and avg stars numbers. These hero display numbers use `font-black` (900) for maximum visual impact on the export card — this weight is exclusive to the export-only render target and must not appear in any live interactive UI element. Body text within the card uses `font-sans` (Inter) at 14px weight 400.

Source: existing heading and label patterns across `RecruitingPage.tsx`, `RosterPage.tsx`, `DraftTrackerPage.tsx`.

## Interaction Contracts

Precise behavior specifications the executor must implement without ambiguity.

### Hard Sell Banner — Live Computation

- Computed on every render when all 3 motivation grade `<select>` elements have non-empty values
- No debounce needed — `getHardSellRecommendation()` is synchronous and cheap
- Banner mounts with a CSS transition: `transition-all duration-150` (fade in — do not animate on the result text itself)
- Banner unmounts immediately when any grade is cleared to empty

### isCommitted Toggle — Optimistic Update

- Toggle calls `updateRecruit(recruit.id, { isCommitted: !recruit.isCommitted })` in recruiting-store
- Optimistic: update local state immediately, persist async
- On error: revert toggle and show toast error via `useToastStore`
- The "Add to Roster" button appears/disappears in the same render cycle as the toggle state change (no animation needed)

### Add to Roster — Modal Pre-fill

- Split `recruit.name` into firstName/lastName by splitting on the last space character: `const parts = name.trim().split(' '); const lastName = parts.pop(); const firstName = parts.join(' ')`
- Pass to `AddPlayerModal` as controlled initial values — the modal must accept these as optional initial-value props (executor should add `initialFirstName?`, `initialLastName?`, `initialPosition?`, `initialStars?` props to `AddPlayerModal`)
- After `AddPlayerModal` saves successfully, the recruit record is NOT modified — it remains as historical class record (D-03)

### Player Combobox — Search Behavior

- Filter on every keystroke (case-insensitive substring match on `${player.firstName} ${player.lastName}`)
- Show dropdown on input focus if input is non-empty
- Close dropdown on blur with 150ms delay (Phase 22 pattern)
- Selecting a list item: set `form.playerId`, auto-fill `form.playerName` and `form.position`, close dropdown
- Clearing input to empty: set `form.playerId = ''`, clear auto-filled fields

### Draft Pick → Player Status Side Effect

- Fires inside `createDraftPick()` in `draft-service.ts` after `db.draftPicks.add(pick)` succeeds
- Condition: `if (pick.playerId)`
- Update: `await db.players.update(pick.playerId, { status: 'drafted', updatedAt: Date.now() })`
- Always overrides regardless of current status (D-12)
- No UI indicator of this side effect — it is silent; player status change visible on RosterPage next navigation

### Signing Day Class Card — Export Flow

1. User clicks "Export Class Card" button
2. Button enters loading state (`"Generating…"` + spinner)
3. Hidden render target DOM node is populated with class data
4. `html2canvas(cardRef.current)` captures to canvas (640×360)
5. Canvas `.toDataURL('image/png')` → base64 string → `Uint8Array`
6. `dialog.save({ defaultPath: `signing-day-${year}.png`, filters: [{ name: 'PNG', extensions: ['png'] }] })`
7. If path returned (user did not cancel): `writeFile(path, bytes)` via `@tauri-apps/plugin-fs`
8. Show success toast: `"Class card saved to {filename}"`
9. Button returns to idle state
10. If user cancels save dialog: silently return to idle (no error)

Source: D-08, D-09, D-10, CONTEXT.md. Tauri PNG export pattern from STATE.md decisions (html-to-image → base64 → Uint8Array → save() → writeFile()).

**Note:** The CONTEXT.md specifies `html2canvas`. STATE.md records the existing pattern uses `toPng (html-to-image) → base64 → Uint8Array`. Either library produces the same output — executor should use `html2canvas` per D-08 (new dependency, confirmed in CONTEXT.md) and follow the same base64 → Uint8Array → Tauri export chain.
