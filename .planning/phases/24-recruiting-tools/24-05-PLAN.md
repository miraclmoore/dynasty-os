    4) Add the export handler (place above the JSX return, near other handlers):
       ```typescript
       async function handleExportCard() {
         if (!cardRef.current || !activeClass) return;
         setExportingCard(true);
         try {
           const canvas = await html2canvas(cardRef.current, {
             backgroundColor: null,
             scale: 2,
             useCORS: true,
           });
           const dataUrl = canvas.toDataURL('image/png');
           const base64 = dataUrl.replace(/^data:image\/png;base64,/, '');
           const binaryString = atob(base64);
           const bytes = new Uint8Array(binaryString.length);
           for (let i = 0; i < binaryString.length; i++) {
             bytes[i] = binaryString.charCodeAt(i);
           }
           const filePath = await save({
             defaultPath: `signing-day-${activeClass.year}.png`,
             filters: [{ name: 'PNG', extensions: ['png'] }],
           });
           if (!filePath) {
             // user cancelled — silent return to idle
             return;
           }
           await writeFile(filePath, bytes);
           const fileName = filePath.split(/[\\/]/).pop() ?? 'signing-day.png';
           useToastStore.getState().success(`Class card saved to ${fileName}`);
         } catch (err) {
           console.error('[ClassCard] Export failed:', err);
           useToastStore.getState().error('Export failed. Please try again.');
         } finally {
           setExportingCard(false);
         }
       }
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Recruit data → captured DOM → PNG file | Recruit names and stats are rendered as React text nodes, captured by html2canvas, and written to a user-chosen path on disk. |
| User → Tauri save dialog → filesystem | The user controls the destination path; Tauri's `save()` dialog enforces an OS-native chooser (no path injection from app code). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-05-01 | Tampering / XSS | Recruit name in card | mitigate | Names are bound through React text nodes (`{r.name}`), not `dangerouslySetInnerHTML`. html2canvas rasterizes the rendered DOM, so any HTML injection attempt would already have been escaped by React before capture. ASVS V5 input validation. |
| T-24-05-02 | Tampering | File save path | mitigate | The path is supplied by the OS-native `dialog.save()` chooser — app code never constructs the path string. `defaultPath` is a filename hint only. |
| T-24-05-03 | Information Disclosure | Hidden card off-screen | accept | The card is rendered in the same WebView and is not user-visible during normal use; `aria-hidden="true"` keeps it out of accessibility trees. The data on the card is identical to what is already shown elsewhere on RecruitingPage. |
| T-24-05-04 | Denial of Service | html2canvas on large class | accept | Capture cost is bounded by 640×360 @ scale=2 = ~922k pixels. recruitsForClass is in-memory and typically <30 entries. No significant DoS surface. |
| T-24-05-05 | Repudiation | Silent cancel on dialog close | accept | Per UI-SPEC Interaction Contract step 10, cancelling the save dialog returns silently. No toast on cancel — user-driven action, no audit need. |
| T-24-05-06 | Supply chain | New dependency `html2canvas@1.4.1` | mitigate | Pinned to a specific version verified against npm registry on 2025-11-13 (RESEARCH.md). Add to `apps/desktop` only, not workspace root, scoping the blast radius. lockfile pins transitive deps. |
</threat_model>
