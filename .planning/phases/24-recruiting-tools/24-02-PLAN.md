## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → Hard Sell calculator | Free-text grades from form/DB flow into `getHardSellRecommendation`. |
| Recruit name → AddPlayerModal | Recruit name is split client-side and passed as React props to a controlled modal form. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-02-01 | Tampering | Motivation grade input source | mitigate | Switching from free-text/category dropdown to a constrained `Object.keys(GRADE_POINTS)` dropdown enforces ASVS V5 (Input Validation). Only the 13 valid grade strings can be selected; `getHardSellRecommendation` returns `null` on any unknown value as a safety net. |
| T-24-02-02 | Information Disclosure / XSS | Recruit name rendered in row badge / passed to modal | accept | React escapes recruit name as a text node and as `<input value=...>` in AddPlayerModal. No `dangerouslySetInnerHTML`. Name is also already rendered in the existing recruit list — no new exposure. |
| T-24-02-03 | Tampering | Optimistic toggle write to Dexie | mitigate | `updateRecruit` (Plan 01) constrains updatable fields via `Partial<Omit<Recruit, 'id' \| 'dynastyId' \| 'classId' \| 'createdAt'>>`. The toggle handler only ever sends `{ isCommitted: boolean }`. |
| T-24-02-04 | Repudiation | Toggle UX implies persisted state | mitigate | Optimistic update reverts via `getRecruitsByClass` reload on error and surfaces a toast ("Could not save recruit"). User sees the failure rather than a silently-stale toggle. |
</threat_model>
