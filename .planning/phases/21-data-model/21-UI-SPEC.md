## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline badge padding (`px-1.5 py-0.5`) |
| sm | 8px | Compact element spacing (`gap-2`), label-to-input gap (`mb-1`) |
| md | 16px | Default element spacing, form section spacing (`space-y-4`) |
| lg | 24px | Section padding (`px-6`), major form section breaks |
| xl | 32px | Layout gaps, modal header padding |
| 2xl | 48px | Major section breaks between form groups |
| 3xl | 64px | Page-level vertical spacing |

Exceptions: Badge height 24px (`h-6`) and width 36px (`w-9`) for OvrBadge — preserves existing roster badge dimensions (component dimension, not a spacing token). Touch-target minimum 40px height for all select/button rows (`py-2` on `text-sm` inputs = 38px — acceptable for desktop-only Tauri app).

Source: codebase scan of `RosterPage.tsx`, `AddPlayerModal.tsx`, `EditPlayerModal.tsx`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 400 (regular) | 1.4 |
| Heading | 18px (`text-lg`) | 600 (semibold) | 1.2 |
| Display | 20px (`text-xl`) | 600 (semibold) | 1.2 |

Notes:
- All modal form labels use `text-sm text-gray-400` (14px, weight 400) — source: `AddPlayerModal.tsx`, `EditPlayerModal.tsx`.
- Modal headers use `text-lg font-semibold text-white` (18px, weight 600).
- Page headers use `text-xl font-semibold` (20px, weight 600).
- Badge/tag text uses `text-xs font-semibold` (12px, weight 600) — consistent across `STATUS_BADGE`, `OvrBadge`, position chip. Visual difference from `font-medium` is negligible at 12px.
- Two weights only: 400 (regular) for body/labels, 600 (semibold) for all emphasis: headings, display, badges, CTAs.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111827` (`gray-900`) | Page background (`bg-gray-900`) |
| Secondary (30%) | `#1f2937` (`gray-800`) | Modal panels, cards, table rows, sub-headers (`bg-gray-800`) |
| Accent (10%) | `#2563eb` (`blue-600`) | Reserved for specific elements listed below |
| Destructive | `#991b1b` / `text-red-400` bg `red-900/30` | Form validation errors, delete buttons only |

Accent (`blue-600 / blue-500 hover`) reserved for:
1. Primary form submit CTA buttons (Add Player, Save Changes)
2. Focus ring on all inputs and selects (`focus:border-blue-500`)
3. Player name hover state on roster rows (`hover:text-blue-300`)
4. "Log Season" action link on roster row

Dev trait badge colors — these are semantic indicators, NOT accent. Use the following fixed palette (distinct from blue accent):

| Dev Trait | Badge Background | Badge Text | Border |
|-----------|-----------------|------------|--------|
| `normal` | `bg-gray-700/60` | `text-gray-300` | `border-gray-600` |
| `star` | `bg-blue-900/40` | `text-blue-300` | `border-blue-700` |
| `superstar` | `bg-purple-900/40` | `text-purple-300` | `border-purple-700` |
| `xfactor` | `bg-yellow-900/40` | `text-yellow-300` | `border-yellow-600` |

Deal breaker tag on roster row (CFB only):
- Background: `bg-orange-900/40`, text: `text-orange-300`, border: `border-orange-700`
- Label: "DB" (abbreviation) on roster rows for compactness; full label "Deal Breaker" in EditPlayerModal

Redshirt badge on roster row (CFB only):
- Background: `bg-red-900/30`, text: `text-red-400`, border: `border-red-700/40`
- Label: "RS"

Motivation grade badges on recruit card — reuse existing `gradeColor()` function from `RecruitingPage.tsx`:
- A-tier: `text-green-400 bg-green-900/30 border-green-700`
- B-tier: `text-blue-400 bg-blue-900/30 border-blue-700`
- C-tier: `text-yellow-400 bg-yellow-900/30 border-yellow-700`
- D/F-tier: `text-red-400 bg-red-900/30 border-red-700`

Source: `RosterPage.tsx` STATUS_BADGE, OvrBadge, `RecruitingPage.tsx` gradeColor — extended consistently.

## Component Inventory

### New form fields in AddPlayerModal (DMOD-03)

**Dev Trait Selector**
- Control: `<select>` using existing pattern `bg-gray-700 border border-gray-600 rounded-lg px-3 py-2 text-white text-sm focus:outline-none focus:border-blue-500`
- Placement: New row below Position/Jersey# row, spanning full width (single column, not split) — dev trait has no natural peer field in AddPlayerModal at this point
- Options: `— (optional)`, `Normal`, `Star`, `Superstar`, `X-Factor`
- Stored values: `''` → `undefined`, `'normal'`, `'star'`, `'superstar'`, `'xfactor'`
- Label: `Dev Trait` with `(optional)` annotation in `text-xs text-gray-600`

### New form fields in EditPlayerModal (DMOD-03, DMOD-04)

**Dev Trait Selector**
- Same control as AddPlayerModal
- Placement: After Status selector, before Class Year/Recruiting Stars row
- Gating: No sport guard — dev trait is relevant for both CFB and Madden

**Deal Breaker Selector (CFB only)**
- Control: `<select>` — same existing input classes
- Placement: New row below Dev Trait, sport-guarded (`activeDynasty.sport === 'cfb'` or prop-passed sport check)
- Options: `— (none)` + 14 CFB 26 deal breaker categories (see Copywriting section for canonical list)
- Label: `Deal Breaker` with `(optional)` annotation
- Gating: Rendered only when `sport === 'cfb'`

**Redshirt Toggle (CFB only)**
- Control: Custom checkbox-style toggle using existing pattern — label + `<input type="checkbox">` styled with Tailwind
- Implementation: `<label className="flex items-center gap-2 cursor-pointer"><input type="checkbox" className="sr-only" ... /><div className="w-9 h-5 rounded-full ... ">` — use a simple accessible checkbox with visible label, no custom toggle library
- Simpler approach: `<input type="checkbox" className="accent-red-500 w-4 h-4">` with label "Redshirt (RS)" to match app's no-library constraint
- Placement: Same row as Deal Breaker (grid-cols-2), or standalone row if Deal Breaker is absent — always CFB-gated
- Label: `Redshirt` with no optional annotation (boolean is always defined, defaults false)

### New form fields in Recruit add/edit forms (DMOD-05)

**Motivation 1 / 2 / 3 Selectors**
- Control: `<select>` — same existing input classes
- Options: The 14 CFB 26 motivation categories (same list as deal breaker categories)
- Placement: New section below existing recruit fields, labeled "Motivations" as a section header (`text-xs text-gray-500 uppercase tracking-wider`)
- Layout: Three selectors in a row (`grid grid-cols-3 gap-2`) — compact because motivation categories are short strings

**Deal Breaker Motivation Selector**
- Control: `<select>` — same existing input classes
- Placement: Below the three motivation selectors, full-width single column
- Label: `Deal Breaker Motivation` with `(optional)` annotation
- Options: `— (none)` + 14 CFB 26 motivation categories

**Visit Week Selector**
- Control: `<select>` using the bounded-dropdown pattern (decision log: "any field with a known valid range uses select")
- Options: `— (none)`, `Week 1` through `Week 14` (CFB regular season + bowls)
- Stored value: number 1–14 or undefined
- Label: `Official Visit Week` with `(optional)` annotation
- Placement: Same row as another compact field if layout allows; otherwise standalone

### New visual indicators on roster rows (DMOD-03, DMOD-04)

**Dev Trait Badge**
- Pattern: Matches `OvrBadge` pattern — `inline-flex items-center justify-center rounded border text-xs font-semibold`
- Size: `px-1.5 py-0.5` (not fixed width — label length varies)
- Placement: In the Status column alongside the status badge, separated by `gap-1` — OR as a new "Trait" column; prefer injecting into Name cell as a sub-label badge to avoid adding a new table column
- Specific placement: Render as a small badge on the second line below the player name inside the Name cell — `<div className="flex items-center gap-1 mt-0.5">` containing the dev trait badge
- Only render when `player.devTrait` is defined (omit for `undefined`)
- Normal trait: render badge only if explicitly set (not implied by absence)

**Deal Breaker Tag (CFB only)**
- Pattern: `inline-flex items-center px-1.5 py-0.5 rounded border text-xs font-semibold bg-orange-900/40 text-orange-300 border-orange-700`
- Label: `"DB"` (abbreviated to avoid column width impact)
- Placement: Alongside dev trait badge in the Name cell sub-line, CFB-only
- Tooltip on hover: "Deal Breaker: {category}" — use existing `Tooltip.tsx` component pattern

**Redshirt Badge (CFB only)**
- Pattern: `inline-flex items-center px-1.5 py-0.5 rounded border text-xs font-semibold bg-red-900/30 text-red-400 border-red-700/40`
- Label: `"RS"`
- Placement: Alongside dev trait and deal breaker badges in the Name cell sub-line

### Motivation grades on recruit card (DMOD-05)

**Motivation Grade Pills**
- Pattern: Reuse `gradeColor()` from `RecruitingPage.tsx` — `inline-flex items-center px-2 py-0.5 rounded border text-xs font-semibold`
- Render: Three grade pills in a row (`flex gap-1`) labeled `M1`, `M2`, `M3` — only render if the corresponding field is set
- Placement: Below the recruit's name/position/stars line, above any action buttons
- Deal breaker motivation: Render as a fourth pill with label `DB` in orange (`bg-orange-900/40 text-orange-300 border-orange-700`) when set

The inline form pattern from Phase 12-06 (momentForms Record per rivalId) is already in place. Phase 21 only adds the DB table and type — no new visual contract needed beyond confirming that exported/imported moments survive the round-trip (data integrity, not new UI).

## Interaction Contracts

### Dev Trait Selector — state transitions
- Default: `undefined` (no badge on roster row; `— (optional)` selected in form)
- On save with `''` → store `undefined` (no field written)
- On save with non-empty value → store `'normal' | 'star' | 'superstar' | 'xfactor'`
- Badge renders on roster row only when `player.devTrait !== undefined`

### Redshirt Toggle — state
- Default: `false` (not redshirted)
- Toggle fires `updatePlayer` immediately on change (no deferred save needed — boolean has no validation dependency)
- RS badge renders when `player.isRedshirt === true`

### Motivation grades — display rule
- Render M1/M2/M3 pills on recruit card only when the corresponding field is a non-empty string
- Deal breaker motivation pill renders only when `recruit.dealBreakerMotivation` is non-empty
- Visit week renders as plain text `"Week {n}"` on recruit card, no pill style

### Sport gating — form fields
- `dealBreaker`, `isRedshirt` in EditPlayerModal: render only when `sport === 'cfb'`
- Motivation fields, deal breaker motivation, visit week in recruit forms: always visible (recruiting is CFB-only already)
- `bowlOpponent` in SeasonEndModal: render only when `sport === 'cfb'`
- Dev trait selector: render in both AddPlayerModal and EditPlayerModal regardless of sport (both CFB and Madden track dev traits)

### Form layout — no new modals
Phase 21 adds fields to existing modals only. No new modal dialogs, no new pages. All additions follow the existing `p-5 space-y-4` form body pattern.
