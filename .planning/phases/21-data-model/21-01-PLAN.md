<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TypeScript compiler → runtime | Compile-time field optionality is the only contract; runtime accepts any shape. Migration code in Plan 21-02 must defensively validate. |
| Browser IndexedDB → Dexie schema | A user importing a v1 export file (or with a corrupted IndexedDB) cannot bypass schema, but old version() blocks must remain to support upgrade-only flows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering | Dexie multi-version chain (`dynasty-db.ts`) | mitigate | Preserve every prior `version(N).stores(...)` call verbatim. Acceptance criteria explicitly grep for v1/v4/v5/v6 lines. Removing them silently breaks upgrades from older installs and corrupts IndexedDB on those machines. |
| T-21-02 | Information Disclosure | KeyMoment table (PII risk) | accept | KeyMoment fields (year, description) are user-authored sports trivia — no PII, no credentials, no third-party data. Stored client-side only. Threat is dismissable per ASVS V8.1.1 (data classification: public/non-sensitive). |
| T-21-03 | Denial of Service | Schema migration on large existing DB | accept | v7 migration is additive — Dexie does not rewrite existing rows when adding a new table. Rollout cost is O(1) for existing dynasty data. No mitigation required beyond preserving the version chain. |
| T-21-04 | Tampering | Type union narrowing on `devTrait` | mitigate | The 4-value literal union (`'normal' | 'star' | 'superstar' | 'xfactor'`) is enforced at the type level. UI selectors in Plan 21-03 produce only these strings. Persistence layer accepts the type without validation — defensible because the same TypeScript build emits both producer and consumer code. |
| T-21-05 | Spoofing | Cross-dynasty KeyMoment leakage via index | mitigate | Compound index `[dynastyId+rivalId]` ensures all per-rival queries scope to a single dynasty. Plan 21-02 query callers must use the compound index, not raw `where('rivalId').equals(...)` (which would leak across dynasties on rivalId collision — though rivalId collision should not occur because rivalIds are UUIDs from `generateId()`). Defense-in-depth, not strictly required. |

</threat_model>
